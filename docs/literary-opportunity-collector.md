# Автоматический сборщик литературных конкурсов

Сборщик находит конкурсы в каталоге [«Литературные конкурсы» на ВсеКонкурсы](https://vsekonkursy.ru/tvorcheskie-konkursy/literaturnye-konkursy), открывает страницы найденных публикаций и добавляет в `public.writer_opportunities` только записи, у которых удалось определить будущий дедлайн. Он не изменяет существующие карточки и не показывает дату проверки в интерфейсе.

## Запуск

GitHub Actions запускает сборщик ежедневно в 06:17 UTC, а также вручную через **Actions → Update literary opportunities → Run workflow**. На первом этапе workflow принудительно работает только в `dry-run`: он ничего не записывает в Supabase. Переключение на реальные записи будет отдельным изменением после проверки результатов.

В настройках репозитория **Settings → Secrets and variables → Actions** нужно добавить два repository secrets:

- `SUPABASE_URL` — URL проекта Supabase (Project Settings → API).
- `SUPABASE_SERVICE_ROLE_KEY` — service-role key проекта Supabase. Это секрет с полными правами: его нельзя помещать в `index.html`, публиковать в коде или передавать клиентскому браузеру. Используйте только GitHub Actions Secrets.

Сборщик использует ключ только внутри GitHub Actions. Ключ не записывается в репозиторий.

## Защита от дублей и качество данных

- Перед вставкой загружаются существующие записи и сверяются нормализованный URL и название + дедлайн.
- Триггер и уникальные индексы Supabase остаются последним уровнем защиты от дублей, включая одновременные вставки.
- Источником ссылки остаётся исходная страница конкурса.
- Сборщик пропускает явно завершённые публикации и записи без уверенно распознанного будущего дедлайна.
- Неопределённые сведения об организаторе, формате и взносе не выдумываются: карточка направляет читателя к странице конкурса.
- Сборщик не ставит дату проверки в интерфейс. Поле `verified_at` заполняется только потому, что оно обязательно в текущей схеме базы.

## Ограничения первой версии

Это первый источник и консервативный сборщик, а не универсальный агрегатор всех опен-коллов. Разметка стороннего сайта может измениться; результаты каждого запуска доступны в журнале GitHub Actions. Перед расширением на другие источники нужно проверить качество данных на реальных запусках.
